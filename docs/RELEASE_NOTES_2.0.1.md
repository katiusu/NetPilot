# NetPilot 2.0.1 (24)

本版只加一条通道：**联发科基带的 AT 直写（实验，默认关闭）**。其余行为与 2.0.0 一致，没有界面、参数默认值的改动。

## 这一版做了什么

- 新增 AT 通道：通过 `/dev/socket/rild-atci` 与 modem 直接通信，按 `RESERVED` → `FILESYSTEM` → `ABSTRACT` 三段命名空间依次尝试，逐行超时读取。
- 探测三步：`AT` 握手 → `AT+ERAT=?` 询问方言与参数量 → `AT+ERAT?` 读当前值；回包参数量不足两个时**拒绝写入**，只做只读。
- 写入序列：映射 → 读当前 → 集合已覆盖则直接判定已生效 → `AT+ERAT=<rat>,<prefer>` → 600 ms 后回读，不匹配再等 900 ms 复读一次。
- 制式映射改为显式表：消息空间值（`EratRat`）与位掩码（`GenerationMask`）是不同类型，编译期就不会串位；整族 CDMA 位不参与比较（电信默认模式 27 含 CDMA，禁写会让「恢复默认」失效）。
- 设置页 › 兼容性 新增「AT 直写（联发科实验）」开关与「测试 AT 通道」一行，探测结果会摘要显示并写入日志页。
- AT 生效但系统 framework 回读仍是旧值时，不再误报「写入未被接受」——这是 MTK 的已知现象（RIL 跳过了同值写），日志会写清「重启后回到运营商默认制式」。

## 开关与前提

- **需要 root**（KernelSU / Magisk 授权本应用）。Shizuku 走不通：`/dev/socket/rild-atci` 的 SELinux 标签是 `gsmrild_socket`、DAC 是 `0660 radio`，shell uid 2000 连不上。
- 开关默认关闭，键为 `np_at_write_enabled`。关着的时候探测也不会发。
- 只在 **ITelephony / 权威存储 / settings** 三条通道全部失败之后才尝试 AT。AT 改的是 modem，绕过 framework，前三条看不到它的结果，所以能走系统就不碰 AT。
- 只操作**当前默认数据卡所在槽**。`AT+ERAT` 是 per-slot，写错槽就是改错卡。

## 怎么验证（联发科机器）

1. 装好后进 设置 › 兼容性，打开「AT 直写（联发科实验）」。
2. 点「测试 AT 通道」，把那一行的摘要，和日志页里 `ATPROBE` 那条的完整输出发我。
3. 确认能读到当前制式后，再观察自动降级是否按预期切到 4G。

实测点：`AT+ERAT?` 回包里哪个字段才是「当前 rat」（本版按第 1 与第 3 字段都接受）、方言是单参还是双参——都是照文档与开源实现推断的，需要真机回包确认。

## 已知限制

- 本版在高通开发机上无法触发 MTK 路径（没有 `rild-atci` 也没有 `/dev/radio`），AT 相关代码**未经真机执行**。
- 重启后制式会回到运营商配置的模式，这是 modem 侧行为，本应用不做开机重写。
- 写入后 framework 的制式显示可能不同步，属已知现象（见上）。
- 写错有断网风险：飞航模式开关一次或重启即可复位。自动降级路径上的冷却、无网回滚仍然照旧生效。
